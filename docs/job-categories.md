# 직무별 수집 지원과 판별 기준

이 문서는 현재 제품의 수집 지원 범위와 판별 동작을 설명한다. 검토 중인 [신규 공고용 일반 분류 규칙](classification-rules.md)과 [고정 정답 440개에 대한 평가](analysis/classification-evaluation-v0.5.md)는 아직 제품에 적용하지 않았다.

직무를 먼저 선택하면 해당 분야의 수집을 지원하는 회사가 기업군 아래 표시됩니다. 지원 여부는 회사별 판별 규칙이 구현돼 있다는 뜻이며, 현재 해당 직무의 공고가 존재하거나 모든 회사의 실사이트 수집 검증을 마쳤다는 뜻은 아닙니다.

분야가 특정되지 않은 `Software Engineer`는 제목에 해당 직무가 명시되지 않으면 세부 분야 수집에서 제외합니다. 본문에 기술 이름이나 ‘개발’이라는 단어가 있다는 이유만으로 분류하지 않습니다. `all`은 각 사이트의 구현된 지원 범위를 따릅니다. 다른 포털의 개발 범위는 유지하며, 오늘의집·토스·당근 국내 포털에서 개발·비개발 공고를 함께 지원합니다. 비개발 5분야를 선택하면 현재 지원 회사는 오늘의집·토스 계열사·당근·당근페이입니다.

카카오뱅크·카카오페이증권의 `AI Engineer`/`AI 엔지니어링`은 회사별 예외로 취급합니다. 모델 학습·구현·파인튜닝 또는 서빙/추론 시스템의 개발·설계 등 구체적인 구현 근거를 추가로 요구합니다. 단순 외부 LLM API 활용이나 프롬프트 작성만으로는 포함하지 않습니다. 다른 회사의 모호한 `AI Engineer`는 이 예외를 자동 적용하지 않습니다.

`MLOps`는 별도 지원 분야가 아닙니다. 기존 사이트 어댑터에서 명확한 개발 직무로 판별되면 `전체 공고`에서만 확인하고, MLOps라는 직함만으로 ML 엔지니어나 DevOps/SRE에 자동 포함하지 않습니다.

- LINE studio: 전체 공고, Android, iOS만 지원합니다. 게임 개발사의 모바일 직함을 웹 백엔드 지원으로 간주하지 않습니다.
- IPX, LINE Friends Square: 현재 전체 공고만 지원합니다. 세부 직무 프로필을 확인하지 않은 조합을 임의로 지원 표시하지 않습니다.

따라서 전체 공고는 63개 회사, Android/iOS는 각각 61개 회사, 나머지 개발 세부 분야는 각각 60개 회사, 비개발 5개 분야는 각각 3개 사이트의 12개 회사의 판별 규칙이 등록돼 있습니다. 실제 구현의 기준은 `CompanyRegistry`와 `CategoryClassifier`이며, 회사나 지원 범위를 바꾸면 이 문서도 함께 갱신합니다.

## 회사별 규칙과 중복 처리

`CategoryClassifier`는 `(companyId, categoryId)`로 규칙을 조회합니다. 네이버·토스·카카오·쿠팡·당근·LINE·우아한형제들·오늘의집에 각각 직함 사전이 있고, 계열사의 직함 및 일본어 표현이 다른 경우 별도 규칙을 둡니다. 예를 들어 토스의 `Server Developer`, LINE의 `Server Engineer`, LY 일본의 `サーバーサイド`는 각각 해당 회사 프로필에서 해석합니다.

각 사이트 어댑터의 공식 직무·조직 분류 → 목록 제목으로 후보 선정 → 실제 본문에서 업무 근거 확인 순서입니다. ‘지원 회사’라는 이유로 모호한 공고를 모두 포함하지 않습니다. 한 번의 수집 실행에서는 선택한 분야만 공고에 연결하고, 다른 분야를 자동 추정해 붙이지 않습니다. 같은 공고를 다른 분야 수집에서도 발견하면 카테고리를 추가할 수 있으며, 내용이 같으면 본문·캡처 버전을 중복 저장하지 않습니다. 풀스택은 웹 백엔드/프론트엔드에 자동 포함하지 않습니다.

## 검증 범위

2026-11-14 통합 검증에서 외부 요청 없이 로컬 표본 294개 assertion을 통과했습니다. 개발 8개·비개발 5개 분야의 직함과 본문 근거, 풀스택 양쪽 업무, 모호한 Software Engineer·분석/연구 직무 제외, PM/PO·세일즈·Design Lead, Marketing Designer의 디자인/마케팅 구분, 카카오 계열사 AI 직함의 구현 근거, 회사별 지원 조합을 확인했습니다. 오늘의집 공식 목록 캐시로 후보 30개, URL 중복 제거·정규화·허용 호스트와 경로도 별도 검증했습니다. 실제 버튼 수집 결과는 아래와 같습니다. 이는 모든 회사·분야 조합의 실사이트 수집 성공을 보장하는 전수 검증이 아닙니다.

카카오페이증권의 재오픈 공고에 과거 `closedAt`이 남아 마감으로 숨겨지는 문제를 발견해 현재 종료 상태·명시적인 마감일 기준으로 수정했다. 해당 공고만 한 번 재수집해 진행 중으로 복원했다. 수정 과정에서 마감 상태 자체를 내용 해시에 넣던 기존 동작도 발견했으며, 최종 구현은 상태만 바뀌면 새 캡처·본문 버전을 만들지 않는다. 상태 변경과 과거 해시 호환은 외부 요청 없는 실제 JPA 트랜잭션 표본으로 확인하고 롤백했다. 수정 이전에 생성한 버전·수집 기록은 보존했다.

서버 적용은 사용자가 진행 중이던 전체 수집이 끝난 뒤 수행했으며 기존 302개 공고를 보존했다. 이 작업에서는 위 표본만 수집했고, 전체 기업·분야 조합을 반복 수집하지 않았다. 카카오페이증권 문제 분석을 위한 상세 1회 조회 외에 오류 없는 공고를 별도로 반복 탐색하지 않았다.

화면에서는 14개 분야 탭·API 분야 설명·비개발 지원 회사 한정·분야와 계열사가 표시되는 기록·저장 본문/캡처·자동 읽음을 확인했다. 1440px와 390px에서 페이지 가로 넘침 없이 분야를 스크롤하고, 모바일 수집 창의 고정 하단 버튼이 화면 안에 유지되는 것을 확인했다. 샘플 모드의 오늘의집 디자인 수집 미리보기도 완료했으며 실제 수집 API는 호출하지 않는다.

기획·디자인·마케팅·영업 및 나머지 개발 분야는 로컬 판별·캐시 검증을 포함한 구현 범위다. 이번 버튼 검증에 포함하지 않은 실제 상세 공고까지 모두 검증했다고 간주하지 않는다. 정식 테스트 소스 파일은 추가하지 않았다.


### 비개발 사이트 확장 검증 · 2026-11-15

기획·PM·디자인·마케팅·영업을 토스 9개 계열사와 당근·당근페이로 확장했다. 오늘의집을 포함해 비개발 분야당 3개 사이트·12개 회사가 지원 대상이다. 개발 8개 분야는 유지하고, 당근의 `Software Engineer, Data`·`Software Engineer, Machine Learning` 직함과 본문 근거도 로컬 표본으로 확인했다. 전체 판별 표본은 304개 assertion을 통과했다. 회사별 후보 조건과 실제 버튼 결과는 [비개발 사이트 문서](non-development-sources.md)를 따른다.
