# 직무별 수집 지원과 판별 기준

직무를 먼저 선택하면 해당 분야의 수집을 지원하는 회사가 기업군 아래 표시됩니다. 지원 여부는 회사별 판별 규칙이 구현돼 있다는 뜻이며, 현재 해당 직무의 공고가 존재하거나 모든 회사의 실사이트 수집 검증을 마쳤다는 뜻은 아닙니다.

## 분야

| ID | 화면 이름 | 포함 기준 | 주요 제외 기준 |
| --- | --- | --- | --- |
| `all` | 전체 공고 | 각 회사 어댑터가 지원하는 분야의 공고 | 기존 7개 기업군은 개발 공고만, 오늘의집은 개발·비개발 지원 범위 |

분야가 특정되지 않은 `Software Engineer`는 제목에 해당 직무가 명시되지 않으면 세부 분야 수집에서 제외합니다. 본문에 기술 이름이나 ‘개발’이라는 단어가 있다는 이유만으로 분류하지 않습니다. `all`은 각 사이트의 구현된 지원 범위를 따릅니다. 기존 7개 기업군의 개발 전용 범위는 유지하고, 오늘의집만 개발·비개발 공고를 함께 지원합니다. 비개발 5분야를 선택하면 현재 지원 회사는 오늘의집만 표시합니다.

카카오뱅크·카카오페이증권의 `AI Engineer`/`AI 엔지니어링`은 회사별 예외로 취급합니다. 모델 학습·구현·파인튜닝 또는 서빙/추론 시스템의 개발·설계 등 구체적인 구현 근거를 추가로 요구합니다. 단순 외부 LLM API 활용이나 프롬프트 작성만으로는 포함하지 않습니다. 다른 회사의 모호한 `AI Engineer`는 이 예외를 자동 적용하지 않습니다.

`MLOps`는 별도 지원 분야가 아닙니다. 기존 사이트 어댑터에서 명확한 개발 직무로 판별되면 `전체 공고`에서만 확인하고, MLOps라는 직함만으로 ML 엔지니어나 DevOps/SRE에 자동 포함하지 않습니다.

## 회사별 지원 조합

현재 회사 카탈로그는 8개 기업군, 63개 회사입니다. 다음은 구현된 조합이며 실제 공고 개수와 무관합니다.

| 기업군 | 카탈로그 회사 수 | 구현된 분야 |
| --- | --- | --- |
| 네이버 | 9 | 전체 공고와 개발 8개 세부 분야 |
| 토스 | 9 | 전체 공고와 개발 8개 세부 분야 |
| 카카오 | 12 | 전체 공고와 개발 8개 세부 분야 |
| 쿠팡 | 10 | 전체 공고와 개발 8개 세부 분야 |
| 당근 | 5 | 전체 공고와 개발 8개 세부 분야 |
| LINE | 15 | 아래 회사별 예외를 제외하고 전체 공고와 개발 8개 세부 분야 |
| 우아한형제들 | 2 | 전체 공고와 개발 8개 세부 분야 |
| 오늘의집 | 1 | 전체 공고, 개발 8개 분야, 비개발 5개 분야 |

LINE 회사별 예외:

- LINE studio: 전체 공고, Android, iOS만 지원합니다. 게임 개발사의 모바일 직함을 웹 백엔드 지원으로 간주하지 않습니다.
- IPX, LINE Friends Square: 현재 전체 공고만 지원합니다. 세부 직무 프로필을 확인하지 않은 조합을 임의로 지원 표시하지 않습니다.

따라서 전체 공고는 63개 회사, Android/iOS는 각각 61개 회사, 나머지 개발 세부 분야는 각각 60개 회사, 비개발 5개 분야는 각각 오늘의집 1개 회사의 판별 규칙이 등록돼 있습니다. 실제 구현의 기준은 `CompanyRegistry`와 `CategoryClassifier`이며, 회사나 지원 범위를 바꾸면 이 문서도 함께 갱신합니다.

## 회사별 규칙과 중복 처리

`CategoryClassifier`는 `(companyId, categoryId)`로 규칙을 조회합니다. 네이버·토스·카카오·쿠팡·당근·LINE·우아한형제들·오늘의집에 각각 직함 사전이 있고, 계열사의 직함 및 일본어 표현이 다른 경우 별도 규칙을 둡니다. 예를 들어 토스의 `Server Developer`, LINE의 `Server Engineer`, LY 일본의 `サーバーサイド`는 각각 해당 회사 프로필에서 해석합니다.

각 사이트 어댑터의 공식 직무·조직 분류 → 목록 제목으로 후보 선정 → 실제 본문에서 업무 근거 확인 순서입니다. ‘지원 회사’라는 이유로 모호한 공고를 모두 포함하지 않습니다. 한 번의 수집 실행에서는 선택한 분야만 공고에 연결하고, 다른 분야를 자동 추정해 붙이지 않습니다. 같은 공고를 다른 분야 수집에서도 발견하면 카테고리를 추가할 수 있으며, 내용이 같으면 본문·캡처 버전을 중복 저장하지 않습니다. 풀스택은 웹 백엔드/프론트엔드에 자동 포함하지 않습니다.

## 검증 범위

2026-11-14 통합 검증에서 외부 요청 없이 로컬 표본 294개 assertion을 통과했습니다. 개발 8개·비개발 5개 분야의 직함과 본문 근거, 풀스택 양쪽 업무, 모호한 Software Engineer·분석/연구 직무 제외, PM/PO·세일즈·Design Lead, Marketing Designer의 디자인/마케팅 구분, 카카오 계열사 AI 직함의 구현 근거, 회사별 지원 조합을 확인했습니다. 오늘의집 공식 목록 캐시로 후보 30개, URL 중복 제거·정규화·허용 호스트와 경로도 별도 검증했습니다. 실제 버튼 수집 결과는 통합 적용 후 아래에 기록합니다. 이는 모든 회사·분야 조합의 실사이트 수집 성공을 보장하는 전수 검증이 아닙니다.
