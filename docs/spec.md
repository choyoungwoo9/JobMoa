# JobMoa 제품 스펙

## 사용 환경과 현재 범위

- 개인 전용 로컬 도구다. Kotlin · Spring Boot · Spring Data JPA · MySQL, React 화면을 Docker Compose로 실행한다.
- 기본 화면은 실제 API·DB·Playwright 수집기를 사용한다. `?demo=1`은 별도 localStorage 기반 화면 검토용 샘플이며 실제 수집이나 PNG 캡처가 아니다.
- 기존 공고·읽음·버전·수집 기록은 재시작과 기능 추가 시 유지한다. 데이터 초기화는 사용자가 명시한 경우에만 별도로 수행하며 자동 마이그레이션에서 삭제하지 않는다.

## 수집 사이트·회사·분야

- 기존 네이버·토스·카카오·쿠팡·당근·LINE·우아한형제들 및 등록된 계열사 포털을 유지한다. 추가 공식 사이트의 첫 대상으로 오늘의집(버킷플레이스)을 지원한다.
- 수집 사이트와 회사는 별개다. 하나의 통합 포털에 여러 계열사가 게시할 수 있으며, 회사 카탈로그에서 포털과 지원 분야를 연결한다.
- 수집은 분야 선택 → 해당 분야를 지원하는 기업군·계열사 선택의 두 단계다. 기업군 체크로 지원 계열사를 일괄 선택하고 계열사를 개별 해제할 수 있다.
- 지원 여부는 회사 × 분야 조합의 수집 규칙이 구현됐는지를 뜻한다. 지원하지만 공고가 0건인 경우는 정상 수집이다.
- 목록 메타데이터로 후보를 좁히고 본문 업무 근거로 최종 판별한다. 본문에 직무 단어가 있다는 이유만으로 포함하지 않는다. 불명확한 공고는 수집하지 않으며 확인 필요 보관함을 두지 않는다.
- 구현된 지원 범위와 실제 사이트에서 검증한 표본 범위는 구분한다. 사이트·공고 구조 변경과 접근 제한은 실패 기록에 남긴다.

## 지원 직무와 경계

- 개발: 웹 백엔드, 프론트엔드, Android, iOS, 풀스택, 데이터 엔지니어, ML 엔지니어, DevOps/SRE.
- 비개발의 첫 범위: 기획, PM, 디자인, 마케팅, 영업. 비개발은 오늘의집·토스 계열사·당근·당근페이에서 지원한다. 다른 포털은 기존 개발 범위를 유지하며, 사이트마다 공식 직군과 직함 규칙을 따로 적용한다.
- `all`은 선택한 회사에서 구현된 수집 범위의 전체 공고다. 각 회사의 구현된 지원 범위를 따르며 토스·당근 국내·오늘의집은 지원하는 개발·비개발 분야를 포함한다.
- 풀스택은 독립 분야다. 웹 백엔드·프론트엔드에 자동으로 포함하지 않고 웹 UI와 서버 개발 양쪽의 업무 근거가 필요하다.
- 데이터 엔지니어와 데이터 분석가·사이언티스트를 구분한다. ML 엔지니어는 모델 구현·학습·추론 서비스 업무를 확인하며 순수 연구 직무는 제외한다.
- 일반 Software Engineer, 막연한 운영·매니저처럼 분야를 특정하지 못하는 직함은 직무별 목록에 임의 배치하지 않는다.
- 분야별 구체적인 포함·제외 기준과 회사별 지원 범위는 [직무 분류 기준](job-categories.md)에 기록한다.

## 공통 큐와 저장

- 실행에는 선택한 분야·계열사를 저장한다. 포털별 목록 탐색은 독립 작업이고 공고는 공통 MySQL 큐에서 빈 작업자가 가져간다.
- 기업별 전담 작업자를 두지 않는다. 작업자 수와 사이트별 동시 활성 페이지 수를 별도 설정한다. 기본 작업자 3개·사이트별 1개이며 전체 반복 수집을 최소화한다.
- 작업자는 자신의 스레드에서만 Playwright와 브라우저를 생성·재사용·종료한다. 쿠팡 상세는 일반 브라우저 모드와 Docker 내부 Xvfb 화면을 사용한다.
- DB에는 대기·처리 중·완료·실패와 단계별 체크포인트·임대 토큰을 저장한다. 재시작 시 임대 만료 작업을 복구한다. 브라우저 탐색·캡처는 DB 트랜잭션 밖에서 수행한다.
- 동일 URL로 식별되는 공고는 공유하고 여러 분야 카테고리를 연결할 수 있다. `all`은 별도 공고 태그가 아니다. 읽음·최초 발견일·버전도 공고 단위로 공유한다.
- 새 분야 수집에서 같은 공고를 발견하면 해당 실행의 분야를 추가한다. 아직 수집하지 않은 분야까지 자동 추정해 붙이지 않는다.
- 본문 해시를 캡처 전에 비교한다. 동일하면 기존 버전·캡처를 재사용하여 본문과 캡처를 다시 저장하지 않는다. 변경 시에만 새 버전을 보관하고 최초 발견일을 유지한다. 마감 상태만 변경된 경우 본문·캡처 버전을 추가하지 않고 상태만 갱신한다.
- 완료 작업의 임시 본문은 제거하고 본문 원본은 버전에 보관한다.
- 마감 공고는 보존하되 기본 목록에서 숨긴다. 목록 누락·일시적인 조회 실패만으로 마감을 확정하지 않는다.

## 공고 탐색과 개인 관리

- 전체 조회와 분야별 조회를 제공한다. 회사·공고명·근무지를 검색하고 최초 발견일 최신순·오래된순 또는 회사 이름순으로 정렬한다.
- 목록 정보는 회사·공고명·근무지·원문 링크·최초 발견일·카테고리·읽음이다. 경력·마감일은 모든 사이트의 공통 필수 추출값이 아니다.
- 왼쪽 목록과 오른쪽 저장된 본문을 함께 표시한다. 캡처는 보기 버튼을 눌렀을 때만 로드·확대한다. iframe을 사용하지 않고 원문은 새 탭으로 연다.
- 열람 시 자동 읽음 처리하며 안 읽음으로 되돌릴 수 있다. 이전·다음 탐색은 안 읽은 목록의 자동 변경에도 탐색 시작 순서를 유지한다.
- 지원 상태·메모·로그인은 현재 범위 밖이다.

## 수집 기록·실패·검증

- 버튼으로 시작한 실행마다 기록 하나를 남긴다. 분야·선택 회사·시각·소요 시간·전체 진행률·기업군별 성공·신규·변경·동일·실패를 표시한다.
- 목록 조회 실패로 집계할 수 없는 값은 `—`로 표시하고 실제 0건과 구분한다.
- 실패 상세에는 회사·공고명(알 수 있을 때)·URL·단계·시각·재시도 횟수·오류 원문을 표시한다.
- 실패 전체 또는 항목별로 실패 단계부터 재시도한다. 선택 분야·계열사를 유지하며 캡처 실패 시 저장된 본문을 재추출하지 않는다.
- 재시도는 원 실행과 연결된 별도 기록이다. 복구 성공 시 원 실패 기록에도 해결 여부를 반영한다. 일부 실패해도 성공한 결과는 저장한다.
- 사용자가 실제 버튼을 통한 검증을 허용했다. 표본 회사·분야 조합으로 검증하고 필요 이상의 전체 재수집과 외부 요청을 피한다. 보안 확인 화면은 공고로 보관하지 않는다.

## 채용 통계

- 여러 직군·사이트를 지원한 상태에서 별도 `채용 통계` 화면을 제공한다. 비개발은 3개 공식 사이트·12개 회사, 개발은 8개 세분화 분야를 유지한다.
- 사이트·회사·직무·미분류를 교차 필터하고 사이트/회사/직무별 비교와 공고 목록 이동을 지원한다. 전체는 URL 단위로 중복을 제거하며 다중 카테고리 행의 합계는 겹칠 수 있다.
- 현재 열린 공고·보관 마감·발견 후 경과와, 선택 기간의 신규 발견·마감·재오픈 추이를 구분한다. 한국 시간 7/30/90일 또는 최대 366일을 선택한다.
- 평균 열림 관측 기간은 열림을 처음 확인한 시각부터 마감을 처음 확인한 시각까지다. 실제 게시 기간으로 표현하지 않으며, 아직 열린 공고·최초부터 마감인 공고는 완료 평균에서 제외한다. 표본이 없으면 대기 표시, 재오픈은 새 기간으로 처리한다.
- 성공한 수집은 본문 변경 여부와 무관하게 상태 관측을 저장한다. 실패·제외는 상태를 확정하지 않는다. 기존 데이터는 마지막 상태만 기준점으로 가져오며 과거 마감/재오픈을 추정하지 않는다.
- 수집하지 않은 날은 미관측으로 드러내고 마지막 관측·미확인 공고·표본 수와 관측 간격을 표시한다. 상세 계약은 [채용 통계](statistics.md)에 둔다.

## 문서 유지

기능·지원 범위·판별 규칙·API·실행 흐름을 변경할 때 관련 문서를 함께 갱신한다. 코드 구현 지원과 실제 수집 검증을 구분하고, 과거 검증 당시 공고 수를 현재 데이터 수로 안내하지 않는다. 세부 작업 규칙은 루트 `AGENTS.md`에 둔다.
