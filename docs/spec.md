# JobMoa 화면 검토 스펙

## 사용 환경

- 개인 전용. 로컬에서 필요할 때 실행하고 버튼으로 수집 시작.
- 현재는 샘플 데이터로 프론트부터 검토. 실제 크롤러와 서버 API는 아직 연결하지 않음.
- 이후 백엔드: Kotlin · Spring Boot · JPA · MySQL. Docker Compose로 실행.

## 수집 범위와 저장

- 네이버·토스·카카오·쿠팡·당근·LINE·우아한형제들 및 각 기업군의 전체 계열사를 포함하는 것이 목표.
- 명확한 개발 공고만 보수적으로 수집. 애매한 공고 제외. ‘확인 필요’ 보관함 없음.
- 브라우저 렌더링 후 캡처 이미지와 본문 텍스트를 함께 보관하는 방향 검토.
- 목록: 회사, 공고명, 근무지, 원문 링크, 최초 발견일, 읽음 체크.
- 직무·경력·마감일은 추출 가능 여부 확인 후 결정. 현재 목록에서 제외.
- 내용 변경 시 새 캡처·본문 버전 저장, 이전 버전 보존. 최초 발견일 유지.
- 동일한 내용은 확인 결과만 기록하고 새 버전은 만들지 않음.
- 마감 공고 보존, 기본 목록에서 숨김. 수집 실패나 일시 누락을 마감으로 간주하지 않음.

## 공고 탐색

- 왼쪽 목록 + 오른쪽 캡처. 필요하면 캡처 확대.
- 공고를 열면 캡처 이미지부터 표시하고 자동 읽음 처리. ‘안 읽음으로 변경’ 가능.
- 상세 이전·다음 버튼으로 연속 열람. 안 읽은 공고를 탐색할 때도 자동 읽음으로 이동 순서가 흔들리지 않도록 탐색 시작 시의 순서 유지.
- 기본 순서는 최초 발견일 최신순. 재수집으로 기존 공고가 위로 올라오지 않음.
- 안 읽은 공고 보기와 마감 포함 토글.
- 개인 관리는 읽음 표시만. 지원 상태·메모·로그인은 현재 범위 밖.

## 수집 기록

- 수집·재시도 버튼으로 시작한 실행마다 기록 하나. 실행 시각, 소요 시간, 전체 결과.
- 실행을 펼치면 기업군별 성공/일부 실패/실패와 신규/변경/동일/실패 건수.
- 목록 조회 실패 시 집계 불가능한 값은 `—`. 실제 확인한 0건과 구별.
- 실패 상세: 기업, 공고명(알 수 있을 때), URL, 단계(목록 조회/본문 추출/캡처/저장), 실패 시각, 재시도 횟수, 오류 원문.
- 실패 항목만 전체/개별 재시도. 실패한 단계부터 이어서 실행. 캡처 실패 시 저장된 본문은 재추출하지 않음.
- 재시도는 별도 실행으로 원 실행과 연결. 원 실패 기록을 유지하고 복구 여부 표시.
- 공고 목록의 마지막 수집 요약 클릭 시 해당 기록으로 이동. 수집 중 기업별 진행 상황 표시.
- 일부 실패해도 성공한 결과와 기존 공고는 보존.

## 서버 구현 시 조사·결정할 항목

- 기업군별 전체 계열사와 채용 사이트 목록. 샘플에 나온 법인은 전체 목록을 의미하지 않음.
- 사이트별 개발 직군 판별 규칙, 공고 식별·중복 제거와 마감 확정 기준.
- 실제 캡처 형식·해상도·파일 저장 위치, 본문·캡처 중 일부 실패 시 저장 상태.
- 내용 변경 판별 시 동적 요소 제외.
- 실제 단계별 재시도, 동시 실행 제한, 재시작 후 상태 복구.

## 프론트 샘플의 한계

React + TypeScript. 공고·본문·캡처 이미지는 모두 예시이며 실제 채용공고가 아님. 원문 링크는 공식 채용 홈으로 연결. SVG 캡처 예시는 실제 브라우저 스크린샷이 아님.

브라우저 localStorage에 샘플 공고·버전·읽음·실행 기록 저장. 수집과 실패 재시도는 열린 탭에서만 실행하는 시뮬레이션.
