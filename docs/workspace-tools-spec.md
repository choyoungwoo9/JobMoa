# 개인 데이터 관리와 공고 검토 도구

기준: 2026-11-16. 기존 공고와 개인 관리 정보를 유지한 채 기능을 추가한다. 실제 수집은 사용자가 실행한다.

## 마이페이지와 초기화

`마이페이지`에서 현재 데이터 건수와 캡처 저장 공간, 백업·복원, 데이터별 초기화를 확인한다.

| 초기화 범위 | 삭제·변경 대상 | 유지 대상 |
| --- | --- | --- |
| 관심 공고 | 모든 공고의 관심 표시·메모·우선순위·지원 상태·지원일. 관심 해제 후 남아 있던 관리 정보도 포함 | 공고·본문·캡처·수집 기록·프리셋 |
| 수집 공고 | 전체 공고·개인 관리 정보·모든 버전·캡처·수집 작업과 실행 기록·통계 관측·변화 요약 | 프리셋 |
| 읽음 상태 | 모든 공고를 안 읽음으로 변경 | 나머지 데이터 |
| 수집 프리셋 | 저장한 직군·회사 선택 조합 | 나머지 데이터 |
| 미사용 캡처 정리 | 어떤 공고 버전이나 수집 작업에서도 참조하지 않는 캡처 | 참조 중인 캡처와 DB 데이터 |

초기화는 범위 설명을 확인하고 `초기화`를 직접 입력한 뒤 실행한다. 미사용 캡처 정리는 `정리`를 입력한다. 실행 중인 수집이 있으면 서버에서도 거부한다. 수집 기록만 따로 삭제하는 옵션은 제공하지 않는다. 기록의 작업 ID가 보관된 버전·통계·변화 기록과 연결되어 있기 때문이다.

DB 변경은 트랜잭션으로 수행한다. 초기화·복원으로 변경된 작업공간 리비전을 조회 응답에 넣어 프론트가 이전 본문 캐시를 재사용하지 않게 한다. 캡처 삭제는 DB 변경 커밋 후 다시 유지보수 잠금을 획득해 참조 없는 파일만 지운다. 수집이 그 사이 시작했거나 파일 정리가 실패하면 DB 변경은 유지되며, 남은 파일은 미사용 캡처 정리로 제거할 수 있다.

## 공고 변경점 비교

상세 화면의 `변경점 비교` 탭에서 선택한 저장 버전과 이전 버전의 본문을 비교한다. 기본 비교 대상은 바로 이전 버전이며 다른 저장 버전도 지정할 수 있다.

- 한국어 문장과 줄바꿈을 기준으로 분리한다. 추가는 초록색 `+`, 삭제는 붉은색 `−`로 표시한다. 번호는 원문 페이지의 줄 번호가 아닌 비교 문장 번호다. 문장 앞뒤 공백만 바뀐 경우에는 변경으로 표시하지 않는다.
- 변경 전후의 같은 문장 3개를 문맥으로 표시하고, 나머지는 생략한다. 전체 본문 옵션을 제공한다.
- 이전 버전이 하나도 없으면 비교할 수 없음을 안내한다. 본문이 같으면 회사명·제목·근무지 변경으로 버전이 생겼을 수 있음을 안내한다.
- 버전당 20만 자를 넘으면 비교 생략을 안내한다. 긴 변경은 계산량 제한을 두고 공통 앞·뒤 문장을 유지한 블록 비교로 전환한다. 캡처 이미지 자체의 픽셀 비교는 범위에 포함하지 않는다.

## 수집 프리셋

수집 창의 직군·회사 선택을 이름(1~80자)과 함께 DB에 저장한다. 첫 단계에서 프리셋을 선택해 즉시 수집하거나 편집·삭제할 수 있다. 하나의 프리셋에 **직군 여러 개 + 회사 여러 곳**을 저장할 수 있다. 기업 선택 단계의 ‘함께 수집할 직군’에서 추가한다. 선택한 직군 중 하나라도 해당하면 하나의 실행·공통 큐에서 처리하며 같은 URL을 직군마다 재수집하지 않는다. ‘전체 공고’와 세부 직군을 동시에 선택할 수는 없다. 회사는 선택 직군 중 하나 이상의 수집을 지원해야 하고, 각 직군도 선택한 회사 중 한 곳 이상에서 지원해야 한다. 후보 탐색과 본문 판별 모두 이 합집합 범위를 적용한다.

저장과 실행 시 실제 회사별 지원 조합을 검증한다. 지원하지 않는 조합을 임의로 다른 직군이나 전체 수집으로 바꾸지 않는다. 프리셋은 공고 초기화 뒤에도 유지되며 백업에도 포함된다. 기존 회사·직군 지원 범위와 보수적인 분류 규칙은 변경하지 않는다.

## 수집 후 변화 요약

마지막 수집 영역과 펼친 수집 기록에 다음 링크를 표시한다.

- 관심 공고 내용 변경
- 관심 공고 새로 마감
- 신규 공고
- 전체 내용 변경
- 전체 새로 마감

건수를 누르면 해당 실행의 공고 ID만 필터링한 목록을 연다. 마감 공고도 볼 수 있도록 마감 포함으로 전환한다. 다른 조회 조건은 초기화하며 변화 요약 필터를 해제할 수 있다.

변화 기록은 작업 저장과 같은 트랜잭션에서 저장한다. `내용 변경`은 기존 본문 해시 비교 결과 CHANGED, `새로 마감`은 이전에는 열려 있었고 이번 확인에서 마감된 상태 전환이다. 신규로 발견한 마감 공고는 마감 전환에 포함하지 않는다. 관심 여부는 공고 저장 시점의 값이며, 이후 관심 해제로 과거 요약을 바꾸지 않는다. 동일 공고를 여러 직군으로 분류해도 실행별 공고 ID를 중복 집계하지 않는다.

이 기능 도입 전 실행의 신규·변경은 완료 작업에서 복구한다. 과거의 관심 여부와 마감 전환은 추정하지 않고 `—` 및 설명으로 안내한다. 수집 완료 뒤 요약을 제공하며 진행 중에는 기존 기업별 진행률을 사용한다.

## 관심 공고 비교

관심 목록에서 공고 2~3개를 선택해 비교 창을 연다. 회사·제목·마감 여부·근무지·분류 직군·우선순위·지원 상태·저장한 메모·최신 저장 본문·원문 링크를 같은 위치에 나란히 표시한다. 작은 화면에서는 비교 영역 안에서 가로로 스크롤한다. 비교 창을 열면 해당 공고의 본문을 가져오고 읽음 처리한다. 비교 창에서는 관리 정보를 편집하지 않으며 상세 화면에서 저장한다.

## 백업과 복원

백업은 공고, 본문 버전, 분류 결과, 관심·메모·지원 기록, 프리셋, 수집 실행·실패 작업·체크포인트, 통계 관측, 실행별 변화 기록과 **참조되는 캡처 파일**을 ZIP 하나로 저장한다. 다른 PC의 동일 백업 스키마를 사용하는 JobMoa에서 복원할 수 있다. DB 접속 정보·애플리케이션 설정·분류 규칙 코드·Flyway 이력·미사용 파일은 포함하지 않는다.

복원은 병합이 아닌 **현재 전체 데이터 교체**다. ZIP 선택 → 파일·스키마·참조·캡처 SHA-256 검증 → 건수 미리보기 → `복원` 입력 → 실행 순서다. 적용 전 현재 데이터 백업을 권장한다. 미리보기는 30분간 유효하며 동시에 2개까지 유지한다. ZIP 파일은 2 GiB, 압축 해제 전체는 4 GiB, 파일 하나와 JSON은 각각 128 MiB, 파일 수는 100,001개, DB 행 합계는 100만 개까지 지원한다. 한도까지의 대용량 성능 검증을 완료했다는 뜻은 아니다.

서버가 지정한 테이블·컬럼 목록만 복원하며 백업에 담긴 SQL은 실행하지 않는다. 경로 이탈, 중복 파일, 누락·손상된 캡처, 다른 스키마, 끊어진 필수 참조를 거부한다. 새 캡처 파일을 먼저 배치한 뒤 FK를 유지한 DB 트랜잭션으로 교체한다. DB 실패 시 기존 DB는 롤백된다. 중단으로 남은 참조 없는 파일은 이후 정리할 수 있다. DB와 파일시스템을 하나의 원자적 트랜잭션으로 보장하지는 않으며, 기존 DB가 참조하는 파일을 먼저 지우지 않는 순서로 일관성을 유지한다.

백업·초기화·복원은 수집 전역 행의 배타 잠금을 사용한다. 읽음·관심 정보·재분류·프리셋 저장은 같은 행의 공유 잠금을 먼저 획득해 유지보수와 쓰기가 교차하지 않게 한다. 외부 사이트 요청 없이 검증할 때는 크롤러 런타임을 끌 수 있다.

## 검증 기록

2026-11-16 임시 DB·저장 디렉터리의 3개 공고/6개 버전/공유 캡처 1개로 API 왕복과 브라우저 버튼 흐름을 검증했다. 백업·초기화·복원, 잘못된 파일 거부, 복원 실패 시 롤백, 다중 직군 공통 큐, 실제 저장 서비스의 관심·마감 변화 기록을 확인했다. 데스크톱과 390px 모바일에서 2~3열 비교와 변경점 표시를 확인했다. 현재 사용자 데이터 건수를 뜻하지 않으며 운영 데이터에는 초기화·복원을 실행하지 않았다. 상세 실행 범위와 lint 제약은 backend/README.md와 frontend/README.md의 같은 날짜 검증 기록을 참고한다. ZIP 상한까지의 부하 검증 및 외부 사이트 재수집은 수행하지 않았다.
