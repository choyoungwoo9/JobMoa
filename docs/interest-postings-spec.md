# 관심 공고 · 지원 후보 관리 스펙

2026-11-15 사이드 대화에서 협의한 다음 기능을 메인 세션에 전달하기 위한 문서다. 사용자가 합의한 스펙의 메인 세션 전달을 요청했다. 합의한 내용을 메인 세션에서 구현하며, 아래 구현 결정을 제품 기준으로 추가한다.

## 목적

수집된 공고 중 지원할 후보를 관심 공고로 모으고 메모·우선순위·지원 여부를 관리한다. 기능 이름은 `관심 공고`를 사용한다.

## 합의한 동작

| 항목 | 동작 |
| --- | --- |
| 관심 등록·해제 | 공고 목록과 상세에서 ☆/★로 추가·해제 |
| 관심 공고 화면 | 별도 메뉴에서 관심 등록된 공고를 모아보기 |
| 기본 탭 | **지원 전** |
| 조회 탭 | 전체 / 지원 전 / 지원 완료 |
| 메모 | 공고마다 자유롭게 작성·수정 |
| 우선순위 | 높음 / 보통 / 낮음 / 미지정 |
| 기본 정렬 | 우선순위 높은 순 |
| 지원 상태 | **지원 전 / 지원 완료 두 단계**. 면접·최종 결과 단계는 추가하지 않음 |
| 지원 완료 | 사용자가 직접 표시하고 지원일을 기록. 잘못 변경했으면 지원 전으로 되돌릴 수 있음 |
| 읽음 | 관심·지원 상태와 별도로 유지 |
| 재수집·내용 변경·마감 | 메모·우선순위·지원 기록·관심 표시 유지. 마감 공고도 보관 |
| 관심 해제 | ★만 해제. **메모·우선순위·지원 기록은 삭제하지 않음** |
| 관심 재등록 | 이전 메모·우선순위·지원 상태·지원일을 그대로 표시 |
| 여러 직군에 연결된 공고 | 기존 공고 원본 하나에 관리 정보를 공유. 직군별로 별도 즐겨찾기나 지원 기록을 만들지 않음 |

사용자는 지원 상태 두 단계, 기본 지원 전 표시, 관심 해제 후 관리 정보 보존을 각각 명시적으로 확인했다.

## 구현 시 유의점

- 관심 여부와 지원 여부는 독립적인 값이다. 관심 해제를 지원 상태 초기화나 관리 정보 삭제로 처리하지 않는다.
- 원문 링크를 여는 동작으로 지원 완료를 자동 판단하지 않는다.
- 개인 관리 정보는 공고 단위로 유지한다. 새 본문·캡처 버전 저장이나 수집 결과 갱신이 이를 덮어쓰지 않게 한다.
- 기존 공고·읽음·수집 기록·캡처를 보존한다.
- 메모 저장 방식, 입력 길이, 같은 우선순위 내 보조 정렬, 지원일 수정 UI 등의 세부 사항은 아직 별도로 합의하지 않았다. 필요하면 기존 화면의 관례에 맞춰 정하거나 메인 세션에서 협의한다.
- 구현에 맞춰 `docs/spec.md`, 루트·프론트·백엔드 README 및 API 문서를 갱신하고, `feat:`·`fix:` 등의 접두사와 한글 설명으로 적절히 커밋을 나눈다.

## 메인 세션에서 이어받을 요청

이 문서를 읽고 관심 공고 기능의 스펙으로 사용한다. 사용자가 이번 사이드 대화에서 요청한 작업은 스펙 협의와 전달까지이며, 사이드 세션에서는 기능 코드·DB·기존 문서를 변경하지 않았다.

## 구현 결정 · 2026-11-16

- 메모는 5,000자까지 입력하고 ‘관리 정보 저장’으로 우선순위·지원 상태·지원일과 함께 명시적으로 저장한다. 저장에 실패하면 입력을 유지한다. 저장 버튼을 누르기 전 변경은 서버에 반영되지 않는다.
- 같은 우선순위에서는 최초 발견일 최신순, 같은 발견일은 공고 ID 내림차순으로 정렬한다. 미지정은 낮음 다음이다.
- 지원 완료를 선택하면 서울 시간의 오늘을 기본 지원일로 제시하고 날짜를 수정할 수 있다. 미래 날짜는 허용하지 않는다. 지원 전으로 되돌려 저장하면 지원일을 비운다.
- 관심 공고 화면은 진입할 때 지원 전·우선순위 높은 순으로 시작한다. 마감 포함은 기본 활성화해 저장한 지원 후보를 놓치지 않게 한다.
- 관심 목록의 검색(메모 포함), 기업군·직군·마감 필터를 제공한다. 상세 탐색 중 관심/지원 상태를 바꿔도 열어둔 공고는 유지하고, 상세를 닫으면 현재 필터를 다시 적용한다.
- 개인 정보는 `posting_interest`에 공고 ID당 하나로 저장한다. 관심 해제 요청과 관리 정보 저장 요청을 분리하여 별표만 해제해도 나머지 필드가 초기화되지 않게 한다.
- 사용자 기존 데이터 초기화나 외부 사이트 재수집 없이 적용한다. 실제 검증 범위와 완료 상태는 구현 검증 후 별도 기록한다.
