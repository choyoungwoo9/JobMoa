# 채용 통계

## 기준과 필터

`채용 통계`는 로컬에 저장한 공고와 성공한 상태 관측을 조회한다. 화면을 열거나 새로고침해도 외부 수집을 실행하지 않는다. 채용 시장 전체의 통계가 아니다.

- 사이트·회사·직무(개발 8개, 비개발 5개, 미분류)를 교차 선택한다.
- 동향 기간은 한국 시간 기준 최근 7/30/90일 또는 직접 입력한 최대 366일이다. 시작·종료일을 포함하며 미래 날짜는 허용하지 않는다.
- 현재 열린 공고·보관 마감·총 공고·미분류·발견 후 경과는 현재 상태다. 기간 필터는 신규 발견·마감/재오픈 관측·마감까지 관측된 기간 평균에 적용한다. 과거 날짜의 전체 재고를 복원하는 화면이 아니다.
- 비교 기준은 사이트별·회사별·직무별이다. 열린 공고 수·신규 발견·평균 관측 기간으로 정렬하고 공고 목록으로 이동할 수 있다.
- 전체 집계는 URL 단위로 중복을 제거한다. 직무별 행은 공고의 현재 카테고리 연결을 사용하므로 여러 직무의 행 합계가 전체보다 클 수 있다. 과거 직무 분포의 스냅샷은 아니다.
- 전체 수집은 분야를 자동으로 붙이지 않는다. 분야별 수집으로 연결하지 않은 공고는 미분류로 집계해 분류 누락을 드러낸다.

## 동향과 평균 기간

신규는 최초 발견일, 마감·재오픈은 성공한 수집에서 상태가 전이한 관측 시각으로 집계한다. 반복해서 같은 상태를 확인해도 마감·재오픈 수가 늘지 않는다. 최초부터 마감인 공고는 마감 전이로 세지 않는다.

`평균 열림 관측 기간`은 열림을 처음 관측한 시각부터 마감을 처음 관측한 시각까지다. 원문 게시일과 실제 마감 시각을 모르므로 평균 게시 기간으로 표시하지 않는다. 선택 기간 중 마감을 관측한 완료 기간만 포함한다. 열려 있는 공고는 평균에서 제외하며 별도로 최초 발견 후 경과 구간(7일 미만/7~30일/30~90일/90일 이상)을 보여준다. 표본이 없으면 0 대신 `—`와 표본 대기를 표시한다.

재오픈하면 새 관측 기간을 시작한다. 같은 공고에서 완료된 기간이 여러 개 생길 수 있으므로 단위는 공고 수가 아닌 기간/회다. 평균·중앙값·표본 수와 마지막 열림 확인→마감 확인 사이 평균 간격을 제공한다. 간격이 길수록 정확한 마감 시각의 불확실성도 커진다. 최초부터 마감된 표본은 완료 평균에 넣지 않는다.

일별 그래프는 계열별 표시를 켜거나 끄고 표로 전환할 수 있다. 성공한 공고 관측이 없는 날은 미관측으로 표시한다. 그날의 0건을 시장에 신규·마감이 없었다는 뜻으로 해석하면 안 된다. 마지막 관측 시각과 기간 내 관측 일수, 7일 이상 미확인된 열린 공고 수를 함께 표시한다.

## 저장과 호환

Flyway V6의 `posting_observation`은 공고 ID·작업 ID·관측 시각·마감 상태·기준점 여부를 저장한다. 성공한 공고 저장과 같은 `TaskService.finish` 트랜잭션에서 기록한다. 내용이 동일해 캡처를 재사용한 작업도 관측을 남기고, 실패·직무 제외는 남기지 않는다. 작업 ID 고유 제약으로 같은 작업의 중복 관측을 막는다. 본문과 캡처 버전 수에는 영향을 주지 않는다.

기존 공고는 마지막 확인 시각과 상태만 기준점으로 가져온다. 과거 마감/재오픈 일자를 만들어 넣지 않는다. 기존 기준점이 열린 상태면 그 시각부터 향후 마감 관측까지 측정하고, 최초 발견 후 경과는 보존된 최초 발견일을 사용한다. 기존 수집 기록이나 버전을 삭제하지 않는다.

통계는 별도 `analytics` 도메인으로 구성한다. 도메인은 순수 관측 집계, application은 필터 검증·조회, infrastructure는 Spring Data JPA 엔티티/저장소, presentation은 API를 담당한다. 목록 메타데이터와 가벼운 상태 이력만 읽고 본문·캡처를 읽지 않는다.

## API

`GET /api/statistics?sourceId=all&companyId=all&categoryId=all&from=2026-11-01&to=2026-11-14&groupBy=source`

- `sourceId`, `companyId`, `categoryId`: 생략/`all`이면 전체. `categoryId=unclassified`로 미분류 선택.
- `groupBy`: `source`(기본), `company`, `category`.
- 기간 생략 시 오늘까지 최근 30일. 잘못된 조합/기간은 400.
- 응답: 집계 시각·기간·필터, 요약, 일별 신규/마감/재오픈/관측 수, 비교 행, 현재 열린 공고 경과 구간.
- 회사 필터로 목록 이동을 위해 공고 메타데이터에 `companyId`를 함께 반환한다.

실제 화면은 30초 간격으로 다시 계산하고 수동 새로고침도 지원한다. 필터 변경 시 이전 요청을 중단하고 다른 조건의 응답을 섞지 않는다. 샘플 모드는 통계 값을 만들지 않고 실제 데이터 화면으로 안내한다.


## 검증 · 2026-11-15

- 순수 도메인 표본 17개 assertion: 재오픈·반복 마감 제외·열린 미완료 기간/최초 마감 제외·기간 밖에서 시작한 표본·마감 날짜 필터·중앙값·다중 카테고리 중복·빈 데이터의 null 평균·일별 합계/관측 일수.
- 실제 API 10가지 조합: 전체·사이트/회사/직무 교차·미수집 직무의 빈 결과·과거 기간에서도 현재 재고 유지·잘못된 회사/사이트/직무/기간/비교 기준의 400.
- 실제 JPA 트랜잭션에서 같은 본문을 두 번 저장할 때 버전 1개·관측 2개, 상태 변경·과거 해시 호환·카테고리 추가·읽음/최초 발견일 유지 확인. 표본은 롤백하고 외부 요청 없이 수행했다.
- 브라우저에서 회사별 공고 이동의 정확한 회사 ID 필터, 미분류 공고 이동, 7일 프리셋·그래프/표 전환·모바일 390px의 페이지 넘침 방지, 긴 회사명 선택 상자·별도 주 메뉴 줄을 확인했다.
- 통계 요청을 브라우저에서 중단시켜 오류 표시→다시 시도→복구를 확인했다. 샘플 모드의 통계 화면은 실제 통계 API를 호출하지 않았다.
- 정식 테스트 소스 파일은 추가하지 않았다. 위 검증은 임시 실행 표본이며 모든 회사·직무 조합을 실제 사이트에서 전수 수집한 결과가 아니다.

상태 관측 이력은 이 기능 도입 이후 쌓인다. 현재 실제 평균이 `—`인 것은 완료된 열림→마감 기간 표본이 없기 때문이며, 보관 마감 수가 있다고 과거 게시 기간을 추정해 채우지 않는다.


비개발 표본 수집 결과는 [사이트별 검증](non-development-sources.md)에 기록한다. 마지막 확인 시점(2026-11-15)에는 보존된 전체 440개 공고와 통계의 총수·열림·미분류·사이트별 합계가 일치했다. 기존 305개 공고의 ID가 모두 보존됐고 기준점 305개·실제 관측 415개, 중복 작업 관측 0개를 확인했다. 이 숫자는 검증 당시의 값이며 현재 데이터 수가 아니다. 별도 전체 수집의 쿠팡 24개 실패(429·정상 렌더링 미확인)는 원 기록에 보존됐고, 실패를 마감이나 성공 관측으로 넣지 않았다.
