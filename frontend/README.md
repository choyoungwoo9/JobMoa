# JobMoa 프론트

React · TypeScript · Vite. 기본 화면은 실제 백엔드 API를 사용합니다.

루트에서 `./start.sh`로 전체 Docker를 실행하고 http://127.0.0.1:15173 에 접속합니다. 종료는 `./stop.sh`. DB와 캡처는 보존됩니다.

개발 서버는 Node.js 22.18 이상에서 실행합니다. 같은 포트의 Docker 프론트는 먼저 종료하세요.

```sh
# 프로젝트 루트
 docker compose stop frontend
 docker compose up -d backend
 cd frontend
 npm ci
 npm run dev
```

Vite는 `/api`를 `127.0.0.1:18080`으로 연결합니다. 15173이 사용 중이면 다른 포트로 바꾸지 않고 종료합니다. 빌드는 `npm run build`이며, 프로덕션 Docker 빌드에서도 같은 소스 자산 검증을 위해 `scripts/`를 포함합니다.

- 전체·직무별 공고 목록, 회사·공고명·근무지 검색, 최초 발견일 정렬, 읽음 체크, 마감 포함.
- 첫 화면은 소개·통계 카드 없이 공고 표를 먼저 보여줍니다. 최근 완료 수집의 시각과 신규·관심 변경·마감·실패 수를 한 줄에 요약하고, 건수를 누르면 해당 공고 또는 수집 기록으로 이동합니다.
- 직군 버튼은 서비스·시스템 개발, 데이터·AI·인프라, 기획·비즈니스·디자인 그룹의 검색 팝오버를 엽니다. 선택 건수는 현재 기업군·회사·마감 필터 범위에 맞춰 보여주며, `전체 직군`으로 초기화할 수 있습니다. 모바일에서는 화면 안에 들어오는 바텀 패널로 표시합니다.
- 공고는 표형 목록에서 회사·공고명·직군 태그·근무지·최초 발견일을 확인합니다. 페이지 크기는 8·20·50개이며 기본 20개입니다.
- 공고명을 누르면 목록 위에 오른쪽 상세 패널이 겹쳐 열립니다. 검색·정렬·페이지·목록 너비를 유지하며 닫으면 기존 위치로 돌아옵니다.
- 브라우저 뒤로·앞으로를 지원합니다. 주요 화면, 공고/관심 상세, 수집 기록 펼침, 수집 창·관심 비교·캡처 확대를 기록하며 검색·필터·정렬·페이지 조작은 현재 항목만 갱신합니다. 뒤로 돌아올 때 공고 목록 문맥과 스크롤을 복원하고, 새로고침해도 현재 앱 상태를 이어갑니다.
- 상세는 저장된 캡처부터 표시하고 열람 시 자동 읽음 처리합니다. 저장 본문·변경점·이전 버전으로 전환할 수 있고 이전·다음 공고 탐색을 지원합니다. 원문은 새 탭으로 엽니다.
- 열 때 자동 읽음, 안 읽음으로 되돌리기, 본문·캡처 이전 버전.
- 직무 선택 → 지원 기업군·계열사 선택 수집, 전체 진행률, 기업군별 성공·신규·변경·동일·실패 집계.
- 실행별 수집 기록, 실패 단계·URL·원문 오류, 전체/개별 실패 항목 재시도.

수집은 사용자가 버튼을 눌러 실행합니다. DB 조회와 상태 갱신은 자동으로 수행합니다. API 연결 실패를 표시하며 샘플 데이터로 자동 대체하지 않습니다.

샘플 검토는 http://127.0.0.1:15173/?demo=1 에서 가능합니다. 샘플 읽음·공고·버전·수집 기록은 별도 localStorage에 저장됩니다. 초기화는 `jobmoa.frontend-preview.v1` 키를 삭제합니다. 샘플 수집은 실제 API를 호출하지 않는 시뮬레이션이며 캡처도 예시 SVG입니다.

공고 목록 UI 시안 비교는 http://127.0.0.1:15173/?mock=postings 에서 확인합니다. 태그 카드형·직군 열 표형·목록+상세형 세 화면을 같은 30개 가상 공고로 비교하며 직군, 검색, 안 읽은 공고, 마감 포함, 페이지 크기를 조작할 수 있습니다. 캡처·본문과 마감 근거는 화면 표현용 예시이고, 이 경로에서는 실제 API·수집·저장 데이터를 사용하지 않습니다. `실제 화면으로 돌아가기` 링크는 일반 화면으로 돌아갑니다.

[전체 안내](../README.md), [확정 스펙](../docs/spec.md), [백엔드·수집 범위](../backend/README.md).

분야와 지원 회사는 `/api/state`의 `categories`, `companies`를 사용합니다. 분야 설명도 API 값을 표시하며, 전체/미분류 탭과 그룹별 직군 선택을 사용합니다. 자동 조회 분류는 개발 세분화와 비개발을 포함한 21개 직군이며 분야별 수집 지원과 구분합니다. 비개발 5개 분야는 오늘의집·토스 계열사·당근·당근페이에서 선택할 수 있습니다. 전체 공고는 각 수집기가 지원하는 범위의 합집합입니다.

같은 공고는 여러 분야에 연결할 수 있고 목록·읽음·버전은 공유합니다. 수집 기록에는 실행 당시 분야와 선택 계열사를 표시합니다. 오늘의집을 포함한 샘플 화면은 예시이며 실제 수집 검증 범위는 [분야 문서](../docs/job-categories.md)와 [오늘의집 수집기](../docs/source-bucketplace.md)를 확인하세요.

샘플 모드도 비개발 분야의 지원 사이트를 오늘의집·토스·당근으로 제한합니다. 샘플의 회사 목록은 화면 검토를 위해 기업군당 한 회사로 단순화합니다.


`채용 통계`는 별도 메뉴와 `Statistics` 컴포넌트로 제공합니다. `/api/statistics`에서 현재 상태·기간별 관측을 조회하며 사이트·회사·세분화 직무·미분류·날짜 필터, 비교 기준/정렬, 그래프/표 전환과 공고 이동을 지원합니다. 30초 갱신과 수동 새로고침은 외부 수집을 시작하지 않습니다. 회사별 공고 이동은 API의 `companyId`로 정확히 필터링합니다. 필터 변경 시 이전 응답을 중단하고 오류·빈 상태·표본 대기를 표시합니다. 모바일 주 메뉴는 별도 줄로 배치하고 긴 비교 표만 가로 스크롤합니다. 기간 정의와 제한은 [통계 문서](../docs/statistics.md)를 참고하세요. 샘플 모드에서는 가짜 통계를 만들지 않고 실제 화면으로 안내합니다.

## 전체 공고 AI 질문

주 메뉴 `AI에게 질문`에서 대화를 저장하고 목록의 모든 저장 공고(열림·마감 포함)를 놓고 질문한다. 서버는 질문과 답변 메시지·작업을 저장한 뒤 작업 ID를 즉시 반환한다. 앱 시작 시 로컬 Codex 워커 연결을 자동 시도하며, 연결되지 않은 경우에도 질문은 대기 상태로 저장된다. 화면은 작업 SSE를 구독해 진행 상태·검색 중 표시·답변 조각을 받는다. 화면을 나갔다 다시 열면 저장된 답변과 마지막 이벤트 ID를 읽고 이어서 구독한다. 답변의 `**강조 문구**`는 굵게 표시하고, `[공고:id]`는 인용된 공고 상세를 여는 인라인 버튼으로 표시한다. 답변이 끝나면 공고 근거와 외부 웹 출처도 각각 링크로 표시한다.

Codex 워커가 연결되지 않은 경우에도 질문은 전송할 수 있고 화면에 대기 상태와 `./ai-worker.sh start` 실행 안내를 표시한다. 앱 시작 때 자동 연결을 시도하며, 동일 대화에서 아직 답변이 끝나지 않은 질문이 있으면 추가 입력을 잠시 막는다. 실패 답변은 다시 시도할 수 있고, 대화 삭제는 질문·답변·작업·출처를 함께 지운다. AI는 수집된 상태나 관심 표시를 변경하지 않는다. 상세 흐름과 API는 [AI 질문 문서](../docs/ai-chat.md)를 참고한다.

## 경력 자료

주 메뉴 `경력 자료`는 `자료 확인 · 등록`과 `추천 · 맞춤 이력서` 두 탭으로 나뉜다. 자료 탭은 여러 파일을 내용 기반으로 판별·추출하고 AI 후보의 원문 인용·위치를 확인한다. 제목·설명을 수정해 저장하고, 잘못된 후보는 제외하거나 다시 추천에 포함할 수 있다. 후보는 별도 확정 없이 기본 추천에 사용된다. 추천 탭은 추천에 포함된 경력 정보가 있을 때 요청할 수 있다. 개수(5·10·15·20)와 선택적인 자연어 희망 방향을 입력하며, 직군·회사 자동완성과 지역은 기본적으로 접힌 `상세 조건`에서 설정한다. 상세 조건은 모두 선택 사항이며, 비워두면 모든 열린 공고를 대상으로 한다. 결과는 ‘잘 맞음 / 검토해볼 만함 / 자료가 부족함’으로 구분한다.

추천 공고에서 공고별 이력서 소개·요약·구성 및 포트폴리오 프로젝트 순서 초안을 요청할 수 있다. 각 초안은 추천에 포함된 경력 근거를 표시하고 복사할 수 있으며 원본 파일을 덮어쓰지 않는다. AI 추출 요약은 원문에서 근거가 확인된 내용만 사용하지만 사용자가 수정·제외할 수 있다. 추천 설정과 마지막 선택 결과는 로컬에 보존한다. 공고 상세를 열면 메인 화면의 브라우저 뒤로·앞으로 탐색 기록에 추천 탭과 선택 결과가 보존되어 다시 돌아올 수 있다.

업로드는 파일당 50 MiB, 한번에 20개와 총 200 MiB까지 허용한다. 읽을 수 없는 파일도 원본과 이유를 표시한다. Codex 워커가 꺼져 있으면 업로드·추출과 추천·초안 요청 저장은 진행되고 AI 작업만 대기한다. 추출 텍스트·파일명, 추천·초안 생성 때 추천에 포함된 경력 정보·선택 공고 본문을 Codex 서비스로 보내며 웹 검색은 사용하지 않는다.

2026-11-22 추천 입력 검증: Node.js 22에서 `npm run build`를 통과했다. 변경한 세 TSX 파일의 Oxlint는 오류 없이 끝났고, 기존 데이터 조회·상태 동기화 effect에서 `react(set-state-in-effect)` 경고 4개가 나왔다. 워크트리 프론트를 `http://127.0.0.1:15175/`에서 열어 상세 조건의 기본 접힘, 펼침, 직군 `웹 백엔드`와 회사 `토스` 자동완성 검색·선택, 접은 뒤 선택 요약 반영을 브라우저로 확인했다. 메인 반영 후에도 같은 흐름을 다시 확인했다. 화면 로딩용 조회만 사용했으며 추천 요청·DB 변경·Codex 작업은 실행하지 않았다.

2026-11-22 경력 정보 자동 반영 검증: Node.js 22의 `npm ci`와 `npm run build`가 통과했다. 경력 자료·추천·마이페이지의 변경 TSX 3개를 Oxlint로 확인했고 오류는 없었으며 기존 동기화 effect 경고 4개가 남았다. 전체 `npm run lint`는 2분 이상 끝나지 않아 중단했다. 재시작한 메인 화면에서 AI 추출 정보가 `추천 반영`으로 표시되고 `수정 저장`·`제외` 동작이 보이며 `확정` 버튼은 없는 것을 확인했다. 추천 화면에서 준비도 문구와 요청 버튼도 새 백엔드 응답에 맞춰 표시됐다. 조회만 했고 수정·제외·추천 요청은 실행하지 않았다.

## 공고별 지원서 원문

공고 상세의 `지원서 정보` 탭은 자동 확인된 원문, 최신 수집 상태·실패 사유, 한 개의 편집 상자와 실제 원문 버전 선택으로 구성한다. 공고 수집 실행에 포함된 열린 공고마다 지원 페이지 확인을 함께 시작하고, 회사별 결과와 지원 페이지 진행률은 공고 수집과 분리해 표시한다. 확인 이력은 실행마다 남기지만 최신 원문과 같으면 새 원문 버전을 만들지 않으며 버전 선택에는 내용이 실제 저장된 행만 표시한다. 최신 확인이 대기·실패 상태면 입력 상자는 비우고, 이전 원문이 있으면 버전 선택에서 열 수 있다. 상태 자동 갱신은 사용자가 입력 중인 초안을 덮어쓰지 않는다. 실패한 공고는 다음 수집 실행에서 다시 시도한다.

원문을 찾지 못하면 입력 상자를 비워 두고 이유를 표시한다. 사용자는 실제 지원 페이지에서 복사한 문항·제출 안내를 붙여넣고 수정해 저장하거나 원문을 복사할 수 있다. 기존 버전은 덮어쓰지 않으며 최신 원문과 동일한 내용은 다시 저장해도 새 버전이 되지 않는다. 공고 본문으로 대체하지 않으며 로그인·폼 입력·파일 업로드·제출을 하지 않는다. 원문 저장만으로 AI에 전송하지 않고 지원 준비 화면에서 문항 추출을 요청할 때만 전달한다.

## 지원 준비 화면

`ApplicationWorkspace`는 관심 공고와 분리된 공고별 지원 건 목록·상세를 제공한다. 공고 상세에서 지원 준비를 시작하며 공고당 한 건만 만든다. `지원 준비`·`지원 완료` 상태는 이 화면에서만 수정하고 관심 목록·상세·비교에는 상태 배지만 표시한다. 예전 관심 공고의 지원 완료 이력은 V18 마이그레이션으로 지원 건에 보존한다.

- 맞춤 자료 탭은 경력 근거가 연결된 이력서·포트폴리오 초안을 만들고 항목을 편집·포함/제외·재정렬한다. 저장 초안은 이 지원 건에만 속하며 경력 원본·추천용 초안을 덮어쓰지 않는다.

- `CollectionChanges`: 마지막 완료 실행과 펼친 기록에서 저장 시점 관심 여부를 기준으로 변화 요약을 표시한다. 항목을 누르면 `App`의 공고 ID 필터로 이동하고, 마감을 포함하며 기존 검색 조건을 초기화한다.
- `InterestComparison`: 관심 목록에서 최대 3개까지 골라 동일 항목을 나란히 보여준다. 모바일에서는 비교 영역만 가로로 스크롤하며 새 버전이 생기면 본문을 다시 조회한다.

서버 `workspaceRevision`이 바뀌면 본문 캐시와 열어둔 상세·비교 및 편집 상태를 버린다. 초기화·복원 후에는 화면을 다시 불러온다. 백업·프리셋·초기화는 실제 API에 연결되며 샘플 모드는 해당 서버 기능을 실행하지 않는다.

격리 API를 대상으로 화면을 확인할 때 `JOBMOA_API_PROXY=http://127.0.0.1:18081 npm run dev -- --port 15175`처럼 프록시 대상을 지정할 수 있다. 기본 API 프록시와 사이트 포트는 각각 18080·15173이다.

## 마감 확인 건수 (2026-11-21)

실제 수집 기록의 기업별 표에 `마감 확인`을 추가했다. 서버의 `SourceResult.closed`를 표시하며 성공 건수의 부분집합이다. 정상 본문을 읽은 결과의 변경·동일과 중복될 수 있다. `동일`은 본문이 같았던 결과, 마감 확인은 종료가 확인된 결과이므로 서로 다른 개념이다. 변화 요약의 `새로 마감`은 상태 전환만 세며 기존 버전·본문·관심 관리 화면은 유지된다. 전체 기준은 [사이트별 공고 마감 판별](../docs/closure-detection.md)을 참고한다. 실제 재수집 버튼 검증은 사용자가 수행한다.

Docker 반영 후 실제 15173번 화면에서 수집 기록을 펼쳐 ‘마감 확인’ 열과 중복 집계 설명이 나타나고 브라우저 오류가 없는 것을 확인했다. 이 검증에서는 수집·재시도 버튼을 누르지 않았다.
