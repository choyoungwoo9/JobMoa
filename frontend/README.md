# JobMoa 프론트

React · TypeScript · Vite. 기본 화면은 실제 백엔드 API를 사용합니다.

루트에서 `./start.sh`로 전체 Docker를 실행하고 http://127.0.0.1:15173 에 접속합니다. 종료는 `./stop.sh`. DB와 캡처는 보존됩니다.

개발 서버는 Node.js 22.18 이상에서 실행합니다. 같은 포트의 Docker 프론트는 먼저 종료하세요.

```sh
# 프로젝트 루트
 docker compose stop frontend
 docker compose up -d backend
 cd frontend
 npm ci
 npm run dev
```

Vite는 `/api`를 `127.0.0.1:18080`으로 연결합니다. 15173이 사용 중이면 다른 포트로 바꾸지 않고 종료합니다. 빌드는 `npm run build`입니다.

- 전체·직무별 공고 목록, 회사·공고명·근무지 검색, 최초 발견일 정렬, 읽음 체크, 마감 포함.
- 왼쪽 목록 + 오른쪽 저장된 본문. 본문은 선택 시 조회하며 이전·다음 탐색을 지원합니다.
- 캡처는 ‘캡처 보기’를 눌러야 불러오며 확대할 수 있습니다. 원문은 새 탭으로 엽니다.
- 열 때 자동 읽음, 안 읽음으로 되돌리기, 본문·캡처 이전 버전.
- 직무 선택 → 지원 기업군·계열사 선택 수집, 전체 진행률, 기업군별 성공·신규·변경·동일·실패 집계.
- 실행별 수집 기록, 실패 단계·URL·원문 오류, 전체/개별 실패 항목 재시도.

수집은 사용자가 버튼을 눌러 실행합니다. DB 조회와 상태 갱신은 자동으로 수행합니다. API 연결 실패를 표시하며 샘플 데이터로 자동 대체하지 않습니다.

샘플 검토는 http://127.0.0.1:15173/?demo=1 에서 가능합니다. 샘플 읽음·공고·버전·수집 기록은 별도 localStorage에 저장됩니다. 초기화는 `jobmoa.frontend-preview.v1` 키를 삭제합니다. 샘플 수집은 실제 API를 호출하지 않는 시뮬레이션이며 캡처도 예시 SVG입니다.

[전체 안내](../README.md), [확정 스펙](../docs/spec.md), [백엔드·수집 범위](../backend/README.md).

분야와 지원 회사는 `/api/state`의 `categories`, `companies`를 사용합니다. 분야 설명도 API 값을 표시하며, 전체/미분류 탭과 그룹별 직군 선택을 사용합니다. 자동 조회 분류는 개발 세분화와 비개발을 포함한 21개 직군이며 분야별 수집 지원과 구분합니다. 비개발 5개 분야는 오늘의집·토스 계열사·당근·당근페이에서 선택할 수 있습니다. 전체 공고는 각 수집기가 지원하는 범위의 합집합입니다.

같은 공고는 여러 분야에 연결할 수 있고 목록·읽음·버전은 공유합니다. 수집 기록에는 실행 당시 분야와 선택 계열사를 표시합니다. 오늘의집을 포함한 샘플 화면은 예시이며 실제 수집 검증 범위는 [분야 문서](../docs/job-categories.md)와 [오늘의집 수집기](../docs/source-bucketplace.md)를 확인하세요.

샘플 모드도 비개발 분야의 지원 사이트를 오늘의집·토스·당근으로 제한합니다. 샘플의 회사 목록은 화면 검토를 위해 기업군당 한 회사로 단순화합니다.


`채용 통계`는 별도 메뉴와 `Statistics` 컴포넌트로 제공합니다. `/api/statistics`에서 현재 상태·기간별 관측을 조회하며 사이트·회사·세분화 직무·미분류·날짜 필터, 비교 기준/정렬, 그래프/표 전환과 공고 이동을 지원합니다. 30초 갱신과 수동 새로고침은 외부 수집을 시작하지 않습니다. 회사별 공고 이동은 API의 `companyId`로 정확히 필터링합니다. 필터 변경 시 이전 응답을 중단하고 오류·빈 상태·표본 대기를 표시합니다. 모바일 주 메뉴는 별도 줄로 배치하고 긴 비교 표만 가로 스크롤합니다. 기간 정의와 제한은 [통계 문서](../docs/statistics.md)를 참고하세요. 샘플 모드에서는 가짜 통계를 만들지 않고 실제 화면으로 안내합니다.

## 직군 분류 화면

목록 상단에 전체 공고·미분류 탭과 그룹별 세부 직군 선택(21개)을 제공합니다. 미분류는 태그가 없는 공고이며 기존 검색·기업·읽음·마감 필터, 이전/다음 탐색, 본문/캡처 보기 동작을 함께 사용합니다. 미분류 또는 분야별 수집 미지원 직군에서 수집 창을 열면 전체 공고로 시작합니다. 직군 선택 건수는 기업군·회사·마감 포함 범위를 반영하며 검색/읽음 조건의 건수는 공고 목록에 표시합니다.

한 공고의 복수 직군을 목록과 상세에 표시합니다. 상세 ‘분류 근거’에서 최신 본문 기준 규칙 버전·시각·판정 문장을 확인하고, 미분류는 이유를 표시합니다. 예전 본문 버전을 열어도 분류는 최신 본문 기준임을 안내합니다. 새 8직군은 자동 분류/조회용이며, 회사별 수집 미지원 분야는 수집 창에서 안내합니다. 통계의 직군 필터도 같은 카탈로그를 사용하고 복수 직군의 합계는 고유 공고 수와 다를 수 있습니다.

## 기업군 로고

공통 `BrandMark`는 8개 기업군의 공식 사이트 아이콘과 공식 앱 아이콘 원본을 `public/logos`에서 표시합니다. 기업군 메뉴·공고 목록·상세·수집 선택·수집 기록에서 같은 자산을 사용합니다. 작은 크기와 기본 크기에서 원본 비율을 유지하고, 이미지 실패 시 기존 문자 마크를 대신 보여줍니다. 옆에 있는 기업명과 중복해서 읽히지 않도록 이미지는 장식 요소로 처리합니다.

외부 이미지 서버 연결 없이 프론트 정적 자산으로 제공하며, [원본 파일과 출처](public/logos/README.md)를 함께 관리합니다. 계열사 고유 CI 대신 소속 기업군의 대표 로고를 표시하는 기존 구분은 유지합니다.

2026-11-15 검증: TypeScript/Vite 프로덕션 빌드와 Docker 프론트 healthcheck 통과. 브라우저에서 공식 자산 8개가 모두 정상 디코딩되는 것을 확인했고, 샘플 공고 상세·기업 선택 8개 로고·이미지 오류 시 문자 대체·1440px/390px 화면의 가로 넘침 없음을 확인했습니다. 수집 시작 버튼은 누르지 않았으며 백엔드/운영 데이터는 변경하지 않았습니다.

## 관심 공고 · 지원 후보

주 메뉴의 관심 공고는 `InterestBoard`에서 제공하며 진입 시 지원 전 탭과 우선순위 높은 순으로 시작합니다. 전체/지원 전/지원 완료를 전환하고 메모 포함 검색·기업군·직군·마감 필터를 사용합니다. 마감 포함은 기본 활성화합니다. 상세 탐색 중 상태를 바꿔도 탐색 목록은 유지하고 상세를 닫으면 필터를 다시 적용합니다.

`InterestStar`는 목록·상세의 ☆/★ 등록/해제만 담당합니다. `InterestEditor`는 메모(최대 5,000자)·우선순위·지원 상태·지원일을 편집한 뒤 저장합니다. 지원 전으로 저장하면 지원일을 비우고 관심 해제 시에는 저장한 모든 관리 정보를 남깁니다. 편집 중인 입력은 1초 폴링으로 덮어쓰지 않으며, 실패하면 입력을 유지합니다. 입력 후 저장 버튼을 누르기 전에는 서버에 반영되지 않습니다. API 응답의 관리 정보 시각을 비교해 늦게 도착한 조회 응답이 방금 저장한 값을 덮어쓰지 않게 합니다.

실제 모드는 관심 API를 사용하고 샘플 모드는 같은 조작을 별도 localStorage에만 저장합니다. 날짜의 기본값·오늘 제한은 Asia/Seoul 기준입니다. 공고별 개인 정보는 직군/본문 버전과 공유하며 원문 열기·읽음 상태는 지원 여부와 무관합니다.
